Rain · falling, collision and splash

补充练习：水滴模型与材质保留老师源工程，以下 Particle Flow、重力和镜头参数由我补齐，不是老师逐值参数。工程通过脚本创建，并在现有 3ds Max 中重新打开、计算与渲染。

Follow the particle

PF Source [Render: Geometry]
  ↓
Rain_Falling
  Birth → Position Icon → Speed → Shape Instance
  → Material Static → Force → Collision Spawn → Delete
                                ↓ spawned particles
Rain_Splash
  Force → Scale → Delete → Collision [Stop]

Build it in Particle View (6)

  1. Create a PF Source. Set Emitter Length / Width to 110 and position Z to 100. Use a Render operator in Geometry mode.
  2. Birth: Emit Start 0, Emit Stop 80, Amount 160. Position Icon places drops across the emitter.
  3. Speed: 90, Variation 15, Divergence 3°. The initial velocity must point down.
  4. Shape Instance: pick Sphere001, Scale 16%, Variation 20%, Acquire Mapping enabled. Material Static: pick the original Drop material.
  5. Create Gravity, Strength 0.25. Its direction must point down; this script-created helper required X Rotation 180°. Add it to the Force operator.
  6. Create Deflector at Z 5, Width / Length 400, Bounce 0.35, Chaos 0.25. Add it to Collision Spawn.
  7. Collision Spawn: Offspring 5, Delete Parent enabled, Offspring Speed = Bounce, Inherited Speed 100%, Divergence 65°, Scale Factor 35%, Scale Variation 20%. Wire its output to a new event called Rain_Splash.
  8. In Rain_Splash, add Force using the same Gravity. Add Scale: Relative First, Sync = Event Duration. Animate X/Y/Z Scale Factor from 100% at frame 0 to 1% at frame 16.
  9. Delete: By Particle Age, Life Span 18, Variation 3. Add Collision using the same Deflector and Speed = Stop to catch returning droplets.

What each setting does

Amount changes how many drops are born. Speed changes their starting velocity. Gravity changes velocity over time. Bounce controls the response at the water surface. Offspring creates the small splash drops. Scale shrinks them; Delete removes them.

Do not confuse the two time systems: the UI uses frames; several scripting properties use ticks. At 30 fps, this scene uses 160 ticks per frame. A node graph alone does not prove the simulation works: reopen the file, evaluate from frame 0, then check actual particles.

Water drop · model + shader

这一节先把 Sphere 做成尖顶水滴，再用渐变和 Falloff 组合明暗、颜色与透明度。源工程 Test4.max 保存了最终 Editable Poly 水滴和材质，所以可以直接查看真实模型与节点。当前学习工程不是 Particle Flow 降雨、碰撞或溅射作业。

1 · Shape the Sphere

  1. 创建 Sphere。进入修改面板，用 Edit Poly / Stretch 调整形状。
  2. 视频约 01:30 出现 Stretch 1.5、Amplify 0、Axis Z，此时形状像两端鼓起的长条。
  3. 约 01:50 出现 Stretch 4.0、Amplify 0.8，并调整 Gizmo 位置，使一端收尖。Gizmo 的位置也影响形状，不能只复制 Stretch 数字。
  4. 约 02:30 试了 Taper Amount −1、Curve 0、Primary Z、Effect XY。这里是课堂中途试形，不是最终堆栈证明。
  5. 后续继续调整并折叠为 Editable Poly。原文件保留最终顶点，未保留完整修改器历史；视频 00:22 可补证起始 Sphere Radius 11.959 cm、Segments 32。学习副本直接保留原网格，不用猜测网格替换它。

2 · Make a grayscale design

先看 Composite #47：两张 Gradient Ramp 做大块明暗，两个 Falloff 分支加入与观察方向相关的细节。此阶段先不要纠结蓝色。

先跟做最初两个节点 · 04:25–08:35

下面是视频早期阶段，不是最终蓝色材质。先在另存的练习副本中看懂两条线，再继续下方 Composite 组合。

  1. 创建 Arnold Standard Surface，命名 Drop，赋给水滴。04:25 可见该材质节点。
  2. 加入 Falloff #45。04:35 面板：Front 黑、Side 白，两者 Amount 100；Falloff Type = Perpendicular / Parallel，Falloff Direction = Viewing Direction (Camera Z-Axis)，初始 Mix Curve 为直线。连接输出到 Drop 的 opacity；05:35 原片已明确显示这条线。
  3. 加入 Gradient Ramp #46，连接到 emission_color，不要接到它上方的 emission 数值端口。05:55 已显示两条线。
  4. 08:15 面板读数：Base = 1.0、Specular = 0.0、Emission = 0.2。这是早期练习状态；保存工程后期为 Base 0、Specular 0、Emission 0.8。
  5. 08:35 的 #46：Gradient Type = Linear、Interpolation = Linear、Noise Amount = 0；Map Channel 1，U/V Offset 0，U/V Tiling 1，U/V/W Angle 0，Blur 1。此时为黑到白的灰度渐变。

4 · Connect opacity separately

Falloff #45 → Drop.Opacity

Opacity 白色保留表面，黑色让表面透明，中间值部分透明。它与 Emission Color 是两条连接线。只把所有贴图接到 Emission Color，无法复制原工程的透明效果。

原材质为 Arnold Standard Surface：Base 0、Specular 0、Emission 0.8。蓝色效果主要由发光贴图绘制，不应把它解释成已配置真实玻璃折射。

5 · Learn by isolating one branch

  1. 另存一份练习档，关闭 Auto Key。
  2. 暂时断开 Opacity 贴图并把 Opacity 设为白色：观察完整轮廓，再恢复 #45。
  3. 把 Composite #56 Layer 2 Opacity 暂设 0：看 #55 分支贡献了哪块亮部，再恢复 100。
  4. 移动观察镜头看 Falloff 如何变化。使用练习副本，保持源工程不动。

Editable source-model study

Download MAX · Model and camera readback

使用源模型、材质和场景，补充了观察镜头，在现有 Max 窗口通过脚本渲染。镜头不是老师原相机的精确恢复。水面有贴图动画，水滴模型未读到变换关键帧。

补齐建模起步：Soft Selection

原片 00:45 的堆栈是 Sphere 上添加 Edit Poly，并进入 Vertex 模式。01:00 已看到尖顶水滴、顶部暖色顶点和向下逐渐变冷的选区。这是 Stretch 试形之前的步骤，不能省略成只调 Stretch。

  1. 在练习副本上给 Sphere 添加 Edit Poly，进入 Vertex，选择顶部要拉动的顶点。
  2. 展开 Soft Selection，启用 Use Soft Selection。01:00 画面可读：Falloff = 20.0 cm、Pinch = 0.0、Bubble = 0.0，Affect Backfacing 已勾选。
  3. 向上移动顶部顶点：附近顶点随之移动，越远移动越少。红／橙／黄／蓝显示影响范围，不是材质颜色。这里的拉动距离与精确选择数量尚未核定，不把当前物体坐标当作位移量。

Falloff 决定影响范围；数值相同但球体大小不同，外形也会不同。原片后面还试了 Stretch 和 Taper，它们是后续试形，不能把所有中途设置直接累加成最终堆栈。起始 Sphere 参数已由 00:22 画面补证；已确认约 03:08 变为 Editable Poly，随后在 Element 层级收窄水滴；转换前的 Gizmo 精确偏移仍待核对。

03:05–03:25 · Convert to Editable Poly and narrow the drop

  1. 03:05 原片打开 Convert To 菜单。03:08 后堆栈显示 Editable Poly，原来的 Taper / Stretch 已折叠进顶点。

先理解这条接线

Birth → Position Icon → Speed → Force → Collision Spawn → Shape Instance + Material Static + Delete。

前半段复制现有雨滴的出生、位置、速度和重力设置，隐藏这些复制出来的下落粒子；碰撞后只生成一个水圈。原分支继续生成五颗飞溅粒子，因此水圈和飞溅可以共存。

在Particle View里跟做

  1. 打开04工程，按6。找到Impact_Ripple_PF_SUPPLEMENT、Ripple_Falling_Copy与Ripple_Expanding。回到Frame 0再播放，Frame 15之后可以观察水圈。
  2. 复制分支沿用原雨滴的Birth、Position Icon、Speed、Force参数及随机种子。此处为Copy，不是自动联动的Instance；以后修改原雨滴参数时，两条分支都要更新，并重新核对落点。
  3. 下落事件中的Render设为Geometry、Visible = 0，避免出现重复雨滴。水圈事件另设Render：Geometry、Visible = 100。
  4. Collision Spawn：Deflectors列表选择Water_Deflector；Number of Offsprings = 1、Delete Parent = On、Restart Particle Age = On、Speed Inherited = 0、Speed Variation = 0、Divergence = 0、Scale Factor = 100、Scale Variation = 0。碰撞后产生一个静止中心。
  5. Shape Instance：选择Impact_Ring_Template_SUPPLEMENT，Animated Shape = On、Fast Shape Evaluation = Off、Sync By = Event Start、Scale = 100、Variation = 0、Acquire Material = Off。每一圈从进入事件时开始自己的形状动画，不会所有水圈一起长大。
  6. Material Static：选择Impact_Ring_Material_SUPPLEMENT。Arnold材质Base = 0.2、Base Color = RGB [110,185,230]、Specular = 0.3、Specular Roughness = 0.25、Emission = 0.5、Emission Color与Base Color相同。它负责浅蓝颜色和可见亮度。
  7. Delete：By Particle Age、Life Span = 18 frames、Variation = 0。水圈寿命是18帧；并非时间轴走到18帧就删除所有水圈。

雨滴修正：飞溅粒子的均匀缩小

重新打开原有Rain_Animated_Study.max并从Frame 0顺序计算到120后，发现教学文字与工程不一致：原工程起始X Scale Factor为50，Y/Z为100。实际飞溅粒子的X缩放也约为Y/Z的一半。这是补充练习内部的不一致，不是老师原片参数。

已另存03_Uniform_Splash_Scale.max，三个轴统一从100%缩到1%，保留原工程供对照。重新打开修正版，逐帧计算0–120，并每4帧读取全部飞溅粒子的三个轴缩放，采样均通过一致性检查，最后粒子归零。

在 Particle View 中怎样改

  1. 按6打开Particle View，找到Rain_Splash事件内的Splash_Shrink（Scale）。
  2. 保留Type = Relative First、Sync = Event Duration。这里的0–16帧是进入飞溅事件后的时间。
  3. 取消Constrain Scale，分别明确设置X/Y/Z；这样编辑一个轴不会意外改变另一个轴。三个轴各有相同的关键帧，结果仍是均匀缩小。
  4. 开启Auto Key，在Frame 0将X/Y/Z Scale Factor都设为100%，Frame 16都设为1%；关闭Auto Key。
  5. 从时间线开头重新计算，比较同一飞溅粒子的大小。不要只跳到终帧检查节点数值。
